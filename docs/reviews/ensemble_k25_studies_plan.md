# Real-time MPC studies with first-interval weight 25

The January ensemble and deterministic yearly configurations are study preparations. No historical optimization has been launched for these configurations. Confirm full input preflight and present the concrete execution plan for approval before a run.

The January study, `configs/research/ensemble_k25_january_2026.yaml`, compares tracking, unweighted shared-first ensemble MPC and weight-25 shared-first ensemble MPC for farms 1 and 345 over 1–31 January 2026. The deterministic study, `configs/research/deterministic_k25_full_year_2026.yaml`, compares tracking, original deterministic MPC and weight-25 deterministic MPC for the same farms during all of 2026. The optional `configs/research/deterministic_k25_jan_aug_2026.yaml` covers the originally requested January–August period. The previous eight-month ensemble draft is superseded; do not run it.

Each trajectory is continuous with its own auction reoptimization and actual state. Both MPC approaches include the planned IDA3 order from IDA2 until the actual IDA3 order is submitted. The current interval-average realized PV is disclosed, an optimistic retrospective information assumption. The ensemble has 50 frozen preceding-day 00 UTC weather members and one updating deterministic member, with raw uniform 1/51 weights. Its first battery and utilization action is shared and later controls are separately scheduled per member, assuming full future-path revelation after the root. The deterministic study requires no ensemble data.

For future January–August deterministic launches, the original MPC minimizes total absolute imbalance in MWh; K=25 instead weights the current interval 25 times. After a primary optimum within the solver's configured MIP gap, a second solve minimizes battery wear and import costs subject to a 1e-7 MWh weighted-imbalance tolerance. A 50% SOC equality applies to every auction-planning delivery day and every daily MPC horizon; no terminal SOC soft penalty or EUR 500/MWh MPC imbalance multiplier is applied. If no valid MPC plan is available, the grid tracker executes that interval, the fallback and its reason are recorded, and MPC tries again on the next interval. The hard SOC target is not guaranteed when the tracker takes over; actual execution may also deviate from a planned target when physical observations or protection differ. The already-running batch retains its previous auction target scope and soft MPC objective. The other study YAMLs retain their own configured objectives. The tracking baseline remains a greedy physical controller. Initial and final-study SOC are 50%; curtailment recovery is disabled.

Both studies use the current reviewed four-cycle model bundles from the receiving checkout at `models/pv/reviewed_four_cycle_2026_selected/`. Their deterministic and weather-member predictions use complete 48-hour issue contexts, then are sliced to required intervals; every eligible deterministic cycle obeys the six-hour release assumption. The issue-context weather fingerprint and selected vintage are recorded. Predictions are zero in configured local monthly night windows. The 31 December ensemble issue used on 1 January is missing most pre-delivery weather. At the user's direction, only missing pre-delivery context values are filled from the eligible deterministic forecast of the identical vintage. Filled features, interval IDs and donor fingerprint are recorded. This is an explicitly modeled surrogate shared by members for missing context, not a measured or ensemble forecast. Missing delivery weather is not substituted by this policy.

The four-cycle models were trained on 2025 historical GHI, use forecast GHI in validation/test, and were selected using January–April 2026 validation. Thus January is retrospective and validation-selected, and May–August test results have previously been inspected. The conservative registry timestamp `2026-11-09T00:00:00Z` indicates retrospective selection, not proof of original historical model availability. Auction planning uses actual historical auction prices as an oracle; settlement uses actual prices. Reviewed curated actual PV targets include explicitly labeled synthetic counterfactual replacements, with retained excluded daylight filled only from historical-GHI pvlib. No unresolved target gaps are silently filled.

Real-data one-day preflights passed for farms 1 and 345 on 1 January, including the approved context fill, and for farm 1 on 15 January with complete preceding-day context. They are input checks and do not run optimization. The full January preflight for both farms was stopped at the user request to free the shared machine; it must be completed successfully on the destination machine before launching January jobs. The launcher now starts two farm processes with one native thread and five Gurobi threads each; the prior preflights used one solver thread per farm. The solver-thread setting is configured per study in YAML; MPC decisions have a ten-second total budget and relative MIP gap 1e-4. Record realized imbalance, signed settlement, auction revenue, degradation, imports, fees, curtailment, inventory, profit, forecasts, fallbacks and runtime. The two representative daily plots comply with the three-day cap. The January plan contains four jobs, 11,904 nominal MPC decisions and 992 nominal auction solves.

The full-year deterministic run also requires a verified extension to the configured auction calendar, which currently rejects dates after 31 August 2026. Its market data coverage must then be preflighted. It currently lacks reviewed actual PV targets after 31 August 2026: the curated farm 1 and 345 tables end at 2026-08-31 21:45 UTC, the final quarter of that local day. September–December reviewed targets and any other missing weather or prices must be provided and preflighted. Do not substitute forecast PV or synthetic power silently. The deterministic January–August variant now ends on 29 August 2026 by user choice: an 8-month replay through 31 August failed because full 48-hour weather issue contexts for the 30 August cycles extend into missing 1 September weather, and ending on 30 August does not eliminate that issue. The shortened variant requires a complete input preflight. A user-approved new run needs new unique run IDs because the current batch runner does not resume a stopped batch.

## Portable launch

The checkout must include or mount `models/pv/reviewed_four_cycle_2026_selected/` (including its manifest and each farm bundle), `data/farms/pv_farms_timeseries_20250101_20260831.zarr`, its matching metadata parquet, the curated target dataset `data/farms/curated/reviewed_ghi_2025_to_2026_08/`, `data/api/market.duckdb`, and for January ensemble the `data/farms/nwp_ens_20260101_20260131.zarr` archive. These model weights are tracked in the main checkout’s `feature/realtime-economic-mpc` branch but are not present in the MPC branch; copy the selected bundle directory from that checkout. The datasets and a valid Gurobi license are not supplied by this MPC branch. Verify model checksums against the provided manifest and use an existing compatible `bess` environment. The launcher does not download data, train models, use GPUs or modify the environment.

Run from the MPC checkout root. Each invocation needs a fresh `--run-id`: the log directory and each farm's study output are never overwritten. The launcher runs farm 1 and farm 345 simultaneously as independent one-worker processes; logs are `outputs/k25_launches/<run-id>/farm_1.log` and `farm_345.log`. Outputs are separate farm run directories in `outputs/energy_research/`.

```bash
python scripts/run_k25_farms.py --study january-ensemble --run-id january_k25_check_v1 --check-only
python scripts/run_k25_farms.py --study january-ensemble --run-id january_k25_run_v1 --run
```

The following prepares the deterministic January–August comparison; its full input preflight has not yet run.

```bash
python scripts/run_k25_farms.py --study january-august-deterministic --run-id deterministic_jan_aug_check_v1 --check-only
python scripts/run_k25_farms.py --study january-august-deterministic --run-id deterministic_jan_aug_run_v1 --run
```

The `year-deterministic` study option is a draft and will fail until the auction calendar, reviewed targets and other inputs cover September–December. Do not interpret a planning-only or one-day check as a full-data pass.
