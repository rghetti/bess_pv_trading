# Shared-first ensemble MPC, first-interval weight 25

Status: draft configurations only. Do not launch a historical study until the forecast-context integration and the relevant complete data preflight have passed, and the concrete execution plan has been approved. No historical optimization was run for these configurations.

`configs/research/ensemble_k25_january_2026.yaml` compares grid tracking, unweighted shared-first ensemble MPC and the same MPC with weight 25 on current-interval absolute imbalance, over 1–31 January 2026 for farms 1 and 345. Each farm's two cases are independent closed-loop optimizations. `configs/research/ensemble_k25_vs_deterministic_jan_aug_2026.yaml` is a draft continuous 1 January–31 August 2026 comparison of grid tracking, ordinary deterministic MPC and shared-first ensemble MPC with weight 25 for the same farms. This is eight months, not a full calendar year.

Both studies use the provisional IDA2 IDA3 plan until IDA3 is submitted, actual current interval-average PV for all scenarios, raw 50 weather trajectories plus the updating deterministic member, uniform 1/51 weights, common first charge/discharge/utilization and separately owned controls from the next interval onward. Future scenario paths are optimistically assumed revealed after the first action. The price-blind objective weights first-interval expected absolute imbalance 25 times and other intervals once, multiplied by EUR 500/MWh, plus the configured wear, import and terminal costs. The single actually issued command executes through protection and the controller replans. Auctions use perfect-foresight actual auction prices, with submissions and finances carried chronologically; each controller can produce different later trades. No curtailment recovery is enabled. The initial and final study SOC are 50%; 10-second Gurobi decision budget, relative MIP gap 1e-4. The per-farm commands should use one worker/solver thread each, with the two farms running concurrently. Compare realized imbalance, signed settlement, auction revenue, wear, imports, fees, curtailment, terminal SOC, profit and fallbacks. Outputs include controller histories, forecast and target provenance, comparisons and plots; limit daily plots to the configured two representative days.

Use the current four-cycle reviewed-GHI bundles from the main checkout, pinned by absolute path. They use 48-hour issue windows and 00/06/12/18 UTC vintages. Training used 2025 historical GHI and synthetic-reviewed targets; January–April 2026 selected models, so January is a retrospective validation-selected period, not an independent evaluation. May–August was test data and has been inspected. The conservative `2026-11-09T00:00:00Z` artifact timestamp in these drafts is a registry cutoff for retrospective labeling, not evidence of historical availability. The causal weather assumption remains cycle plus six hours; raw ensemble cycles are preceding-day 00 UTC. All predicted output is zero during the configured local monthly night windows. Actual PV uses reviewed curated targets including any labeled counterfactual synthetic replacements, with historical-GHI pvlib fills only for retained excluded daylight and no silent unresolved gaps.

Different sequence endpoints alter predictions. `src/simulation/continuous_inputs.py` and `src/simulation/continuous.py` need full issue-window weather preflight and prediction followed by slicing, for deterministic and all ensemble members. A passing existing preflight does not validate this contract. Preserve publication eligibility, nighttime clipping, forecast vintage and fingerprints. Complete, compatible 50-member weather cycles for those dates must be supplied and inventoried; retain per-cycle availability and checksums. The draft lists only the two existing archives and is intentionally incomplete.
